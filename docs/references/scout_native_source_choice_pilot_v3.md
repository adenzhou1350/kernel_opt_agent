# Native source-choice feasibility pilot v3

Freeze before selected implementation/test acquisition or compared model calls.
This is a new three-slot feasibility experiment, not completion or replacement
of either source-inception pilot, the owner-exposed packaging development task,
or the known-command capability checks. None of those results fills a slot here.
The question is whether an evidence-acquisition handoff improves independently
reproduced findings per actual resource use over simpler acquisition and native
direct-agent controls. No bug is required in a slot.

## Common evidence and capacity

All arms receive the same task, commit/path/message/parent metadata, original
tracked source/docs/tests and explicit supported native runtime constraints.
Do not supply an owner's bug suggestion, another arm's answer, historical fixes,
later upstream outcomes or a required finding. Every arm may propose at most
one supported public-contract violation with an executable witness, abstain, or
report incomplete work. Final native submission must be nonempty and identify
which of FINDING/NO_FINDING/INCOMPLETE is claimed, the public contract, witness
path and actual checks/uncertainty as applicable. Presence is not correctness.

Reuse the unchanged pinned Mini default agent/LiteLLM parser and CPU sandbox
adapter. Permit single or multiple native calls, preflighting whole responses;
execute accepted calls individually and sequentially. Never drop extra calls,
concatenate commands, count unexecuted suffixes, or give an arm format repair
outside its original budget. Production Scout remains tool-free.

The original package/source/test inputs are protected by before/after hashes.
Agents may create separate probes/notes, not edit supplied code/tests, install
packages, use network/host credentials or access a GPU. Each action uses the
existing offline nonroot 1CPU/512MiB profile, read-only system, 64 tasks, fresh
container and regular-file-only /work persistence. Unknown execution stops new
dispatch until that same handle/history is resolved. No replay by directory rename.

## Policies

Use this order, cyclically rotated by slot index, one attempt per arm:

1. **rule + M3**: acquisition is three reviewed native reads: entire target,
   deterministic companion source, and deterministic original native test
   observation. Then one MiniMax-M3 final review, without extra exploration.
   The review's final native submission also consumes an action. Absent,
   oversize or unrunnable evidence remains unavailable; no success-driven fallback.
2. **GLM direct**: GLM-5.3 chooses its own supported investigation actions.
3. **M3 direct**: MiniMax-M3 does the same under identical capacity.
4. **GLM acquisition + M3**: at most four GLM queries and four actions, then
   at most four M3 queries and the remaining common action/time allowance.
5. **M3 acquisition + M3**: same split/handoff as arm4, controlling for the
   conversation reset and handoff overhead rather than calling it a new method.

In handoff arms, freeze phase1 before starting phase2. Give the fresh reviewer
the original task and inputs, raw non-submission command observations, and
unchanged generated probe files with their hashes. Exclude phase1 model prose,
reasoning and final-submission output. Verify protected input hashes before
handoff. Charge the phase1 submission command/query if any; do not reinterpret
it as a free discovery result. Phase2 alone supplies the scored prediction.
Early phase1 completion does not increase phase2's four-query ceiling. A stopped
or invalid phase1 remains charged; infrastructure uncertainty stops the case.

GLM/M3 name available configurations, not verified cheap/strong roles. GLM uses
explicit low effort; M3 uses its existing provider defaults. Prices and realized
effort are unknown. Direct Mini uses a published existing general agent as its
loop, not an independently reproduced ReAct/SWE-Search/ARS benchmark. No method
equivalence, novelty or model hierarchy is established by adopting its loop.

## Preparation and bounded resources

Each arm has at most eight queries, eight native actions, 360 decision seconds,
80 seconds/request, 30 seconds/command, 4,096 output tokens/query and 98,304
prepared-message bytes/query. Handoff phases share the eight-action and wall
ceilings; two four-query limits do not grant sixteen actions or two wall budgets.
Rule intentionally uses less capacity: record its realized cost, do not make
the baselines waste unused allowance to appear matched.

Stop an arm after 60,000 inclusive reported tokens, and the study after 300,000
tokens or 99 planned requests, whichever comes first. These are post-response
stops; preserve overshoot. Unknown usage or unsettled provider dispatch stops
new calls for that case, not a zero-cost or no-finding result. No model retries,
provider fallback, answer rescue, second realization or success-selected rerun.

Before model calls, allow 600 seconds of preparation per slot plus one shared
600-second reviewed dependency preparation. Source bundling/build-generated
version metadata may be prepared transparently in a private controller runtime;
retain exact tracked bytes, build inputs, imports and generated artifact hashes.
No fake version module, test rewriting or silent installed-package substitution.
Native observations can reuse that reviewed offline closure. If the package
cannot fit, import or run faithfully in the declared sandbox, keep the failed
or unavailable slot; do not enlarge its profile or replace its tests with AST code.

Choose the companion from original tracked tests by target-stem affinity first,
then sorted path; record the complete candidate list and literal choice before
execution. Native observation is the entire chosen module, retaining original
parametrization/fixtures/skips. If there is no matching module, use the first
sorted top-level test module; if none exists, mark unavailable. No assertion-aware
selection. Read test/build configuration for runtime preparation but do not do
the substantive bug audit before all arm predictions are frozen. Record owner
exposure from preparation and any accidental unblinding.

Record physical source/dependency preparation and native executions once, logical
reads per arm, standalone versus amortized costs, all failed setup and actual
owner time. Cached input is a subset of reported input, not additional tokens.
Equal declared ceilings do not establish priced or equal-compute comparisons.
Do not turn unknown prices/effort or excluded development time into zero.

## Adjudication, misses and interpretation

Freeze every arm prediction before owner adjudication. Strip arm/provider labels,
deduplicate equivalent hypotheses and run the same independent native checks on
each distinct proposed defect. Require the public contract, actual imported
package identity, a discriminating original-source failure and ordinary healthy
controls. A bad generated oracle, infrastructure failure, unsupported input or
unreconciled assertion is not a target defect. Allow 1,200 seconds per slot for
this common adjudication; unresolved proposals stay unresolved.

Then do one separately timed 1,200-second arm-blinded owner source/native audit
per slot for missed defects. Exposure and imperfect blinding remain limitations;
the resulting audited reference set is not exhaustive ground truth or population
recall. Inspect equivalent workloads/contracts rather than rewarding paraphrases.
Report reproduced findings, false/unresolved proposals, audited misses, invalid
outputs, unavailable evidence and actual costs. Incomplete output stays incomplete.

No statistical generalization or paper-readiness claim follows from three slots.
If selection adds cost without useful discrimination, retain that result and
prefer the simpler policy in ordinary work. A future claim still needs verified
model-role/pricing controls, applicable published-method comparisons, substantially
larger independent cohorts and a benefit that survives miss and total-cost audits.
