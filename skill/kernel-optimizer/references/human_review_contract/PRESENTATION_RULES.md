# 人工审核页面规则

## 信息架构

页面按审核时间组织，而不是按工具或 benchmark ID 组织：

1. **十秒总览**：工作负载、硬件、计时口径、按实测时间等宽的阶段时间线；
   每阶段只显示主要限制、直接证据和证据状态。
2. **一分钟阶段审核**：每阶段使用同一模板，左侧为生产计算 DAG，中间为
   以微秒为横轴的角色/资源时间线，右侧为消融条形图或生产工作点曲线。
3. **五分钟资源审核**：按资源展示强制工作量、生产切分、首次服务延迟、
   稳定吞吐、生产工作点、匹配饱和点、未饱和原因和关键路径贡献。
4. **跨阶段边审核**：payload、生产者/消费者所有权、唯一/请求字节、
   请求放大、实验、决策和边界。
5. **缺失证据队列**：集中列出阻止闭合的节点/边以及下一项最小实验。
6. **开发者附录**：默认折叠，包含内部 ID、路径、哈希和复现命令。

## 视觉编码

- 阶段颜色只表示身份，不表示好坏。
- 实线边框：生产匹配；虚线：条件匹配；灰色：仅供方向判断；斜纹：
  尚未测量；红色只表示已否决方案。
- 证据状态和决策状态必须分别显示。
- 一张图只使用一个单位；禁止混合单位热力图。
- 核心 A/B 数字必须紧邻结论，不能只放在 tooltip。
- 不展示主观“完成度”“压力百分比”或未经定义的颜色深浅。
- 容量条只能表示静态占用；服务率条只能表示同一匹配曲线上的工作点。
- 所有首次出现的术语使用 `SEMANTICS.md` 中的中文名称；必要时提供一句
  就地解释，不发明同义词。

## 人类实验名称

主页面使用动作和目的命名，例如：

- 去掉预测矩阵乘
- 去掉状态更新矩阵乘
- 去掉全部矩阵乘
- 仅保留数据搬运与同步
- 改变单次搬运数据量
- 分别运行 A、B 及 A+B
- 合并前后两个阶段

不得使用 M100、case-7、probe-x 等内部代号作为标题。

## 工作点卡片

每个物质资源卡片按固定顺序显示：

1. 强制工作量与单位；
2. 生产切分；
3. 首次服务延迟；
4. 稳定服务时间与吞吐；
5. 生产工作点 / 匹配饱和点；
6. 低于饱和点的已证原因；
7. 关键路径贡献或“尚未测量”；
8. 结论、证据状态和边界。

无法填写的字段显示“尚未测量”，不能隐藏卡片或用估算补齐。
