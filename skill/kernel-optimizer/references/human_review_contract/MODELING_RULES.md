# 建模规则

报告中的每个阶段都按四层建模，不能从峰值规格直接跳到生产结论。

## 1. 工作量模型

冻结目标工作负载和生产切分，逐层统计：

- 有效与 padding 的标量、SFU、SIMT、Tensor Core 工作；
- 唯一数据量、实际请求量、L2/HBM/shared 字节量；
- thread、warp、CTA、grid、cluster 的工作归属；
- 寄存器、shared、barrier 和生产者/消费者交接；
- 数学 DAG 的真依赖与当前调度额外引入的串行边。

任何比例都必须给出分子、分母、单位和适用工作负载。

## 2. 单资源服务模型

使用同机制 repeat sweep 拟合 `T(r)=alpha+beta*r`：

- `repeat=0` 是计时、launch、sink、循环和同步的基础包络；
- 首次服务延迟为 `T(1)-T(0)`；
- 稳定单次服务时间是高 repeat 稳态区间的斜率，不默认等于全局拟合
  `beta`；
- 稳定吞吐为 `每次实际服务工作量 / 稳定单次服务时间`；
- 报告必须说明 sink/checksum 污染、cache 状态和目标指令是否由最终
  SASS 证实。

延迟测试使用依赖链，吞吐测试使用多个独立 accumulator/request。至少
扫描 warp 数、grid/CTA 数、每 CTA 工作量、ILP、驻留限制和 cache 状态，
才能构造匹配饱和点。

生产工作点与匹配饱和点使用相同单位并列展示：

`服务率比例 = 生产工作点服务率 / 匹配饱和点服务率`

若生产服务率无法从阶段总时间中分离，则不计算该比例，标记尚未测量。

## 3. 资源耦合模型

对物质资源对至少测量 A-only、B-only、A+B 串行、A+B 重叠，并保持
几何、分配、工作集和可观察输出。比较 `T(A+B)` 与 `T(A)+T(B)` 以及
`max(T(A),T(B))`，判断：

- 法定重叠是否被实现；
- issue、寄存器、shared、cache、同步或所有权是否产生争用；
- 单资源服务曲线在组合后是否仍可使用。

不存在耦合实验时，不得把各单资源时间直接相加，也不得直接取最大值。

## 4. DAG 调度模型

把每个节点的强制工作映射到匹配服务曲线，把边映射到数据到达、barrier、
ownership handoff 和资源互斥。用 max-plus/离散事件方式计算当前调度和
候选调度，不把可重叠项串行相加。

每个工作负载至少并列：

1. 当前调度预测；
2. 最佳可行调度预测；
3. 生产实测；
4. 预测残差和预注册容差；
5. 未闭合节点、边及其待补实验。

只有跨层满足“微基准预测组件、组件预测生产”后，才能发布理论极限。

## 为什么工作点无法打满

低于匹配饱和点时，只能从下列统一原因中选择，并给出对应扫描证据：

- 全卡并行不足
- 单 CTA 数据量不足
- 独立请求不足
- 驻留数量受限
- 请求放大
- 地址效率不足
- cache 层级不匹配
- 同步截断
- 尾波不均衡
- 与其他资源争用

硬件峰值与生产值的差异本身不能证明任何一项。每个原因必须关联一个
改变该因素、保持其它因素不变的工作点扫描。否则状态是待验证。

## 设备级计算效率拆分

计算资源不能用一个“利用率”覆盖。分别报告：

1. 全卡并行覆盖；
2. 活跃 SM 内效率；
3. 计算器件占空比。

只有三者的测量语义相容时，才可将设备级效率解释为三者的乘积。没有
动态计数时，可用匹配 microbenchmark 的可验证代理，但必须标成条件匹配。
